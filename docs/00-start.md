# 시작 체크리스트 · 과제 분석 및 질문 템플릿

## 0~10분: 읽고 사실을 분리한다

- [ ] 대회 규정과 허용 도구·외부 자료·제출 방식을 확인했다.
- [ ] 제공 README, 데이터, 기존 코드, 실행 명령을 읽었다.
- [ ] 필수 요구사항과 선택 기능을 분리했다.
- [ ] 추정은 `[가정]`, 안내에 없는 것은 `[확인 필요]`로 표시했다.
- [ ] `02-problem-brief.md`를 작성하기 시작했다.

## 10~20분: 문제를 합의한다

- [ ] 실제 사용자와 업무 장면을 한 문장으로 썼다.
- [ ] 병목 또는 실패 비용을 확인했다.
- [ ] 측정 가능한 성공 기준을 하나 이상 정했다.
- [ ] 범위 밖 항목을 명시했다.
- [ ] 구현 방향을 바꿀 질문만 실무자에게 물었다.

## 진행 원칙

1. **핵심 흐름 우선**: 입력 → 처리/판정 → 결과 → 다음 행동을 먼저 끝낸다.
2. **작은 위임**: AI에 한 작업만 맡기고 완료 조건과 검증 방법을 준다.
3. **증거 남기기**: 결정, 테스트 결과, 알려진 한계를 즉시 기록한다.
4. **마감 보호**: 마감 40분 전부터 새 기능을 추가하지 않는다.

### 추가 요청과 확인 항목

- `README의 요구사항을 테스트 가능한 완료 조건으로 바꿔줘.`
- `필수 구현만으로 제출 가능한 가장 작은 작업 계획을 30분 단위로 만들어줘.`
- `각 요구사항이 어느 파일/기능에서 구현될지 매핑해줘.`
- `구현 뒤 직접 실행해 확인할 핵심 사용자 시나리오 3개를 만들어줘.`
- `문서에 남겨야 할 판단 근거, 검증 결과, 알려진 한계를 초안으로 작성해줘.`

- [ ] 필수 파일명·경로·제출 조건이 빠지지 않았는가?
- [ ] “필수”와 “있으면 좋은 기능”이 구분됐는가?
- [ ] 추측으로 정한 내용이 `[확인 필요]`로 표시됐는가?
- [ ] 질문이 핵심 3~5개로 제한됐는가?
- [ ] 실제 실행·테스트 방법이 포함됐는가?

## 실무자 에이전트 질문 템플릿

README 분석 뒤에도 구현 방향을 바꿀 만큼 중요한 불확실성만 짧고 구체적으로 확인합니다.

### 문제와 사용자

```text
제가 이해한 과제 목표는 “[내 이해를 한 문장으로]”입니다. 맞나요?
이 결과물을 실제로 사용하는 사람은 누구이고, 그 사용자가 가장 크게 겪는 문제는 무엇인가요?
```

```text
이번 과제에서 가장 중요한 성공 기준 1~2개는 무엇인가요?
예: 정확성, 빠른 처리, 사용 편의성, 설명 가능성, 특정 업무 흐름 완성 중 무엇을 우선해야 하나요?
```

### 범위와 우선순위

```text
180분 안에 제출할 때 반드시 구현되어야 하는 기능을 우선순위대로 확인하고 싶습니다.
제가 생각한 필수 범위는 ① [기능] ② [기능] ③ [기능]인데, 맞는지와 제외해도 되는 범위를 알려주실 수 있나요?
```

```text
시간이 부족하다면 어떤 기능을 생략해도 되며, 반대로 절대 빠지면 안 되는 사용자 흐름은 무엇인가요?
```

### 동작·데이터·예외

```text
[입력/상황]에서 기대하는 결과가 무엇인지 확인하고 싶습니다.
정상 동작 외에 반드시 처리해야 하는 예외나 실패 상황이 있나요?
```

```text
제공된 데이터/예시 외의 데이터를 가정해도 되나요? 데이터가 없거나 불완전할 때는 어떤 방식으로 보여주는 것이 적절한가요?
```

### 결과물과 검증

```text
제출물에서 반드시 직접 확인되어야 하는 대표 시나리오가 있나요?
제가 브라우저에서 [시나리오]를 시연할 수 있으면 요구사항 충족으로 볼 수 있을까요?
```

```text
기능 구현 외에 README, 계획 문서, 협업/검증 기록에 반드시 담아야 할 내용이 있나요?
```

### 질문 원칙

- 내 해석을 먼저 한 문장으로 제시하고 확인합니다.
- 과제 안내에 있는 내용을 반복해서 묻지 않습니다.
- 답변 뒤에는 “그러면 [결정]으로 구현하겠습니다”라고 짧게 합의합니다.
- 화면 조작·접속·제출 문제는 실무자 에이전트가 아니라 안내된 지원 채널을 사용합니다.

## 최소 실행 흐름

1. README와 과제 안내를 읽습니다.
2. 위 AI 분석 프롬프트로 필수·모호한 점·MVP를 정리합니다.
3. 구현 방향을 바꾸는 불확실성만 실무자 에이전트에게 질문합니다.
4. 확정 답변을 Problem Brief와 Decision Log에 기록합니다.
5. MVP 구현 → 실행 → 브라우저에서 핵심 흐름 검증 → 저장 상태 확인 순서로 진행합니다.
6. 제출 전, 요구사항 체크리스트와 검증 결과를 다시 대조합니다.
